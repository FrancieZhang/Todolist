核心判断Robotaxi 真正领先的不是“把所有技术难题都解决了”，而是把不完美技术约束在明确 ODD 内，并用调度、指标、人工兜底和准入证据做成可运营闭环。人形机器人最应复制的是这套 0→1 商业化系统工程。
机器人难题Robotaxi 状态已经做到仍在进行迁移判断
无围栏安全 / ODD已完成 0→1限定 ODD 内已有感知—规划—执行、最小风险停车、远程协助、准入与运营流程扩 ODD 成本高；高精地图依赖与长尾泛化仍未完成迁移方法，不迁移结论：先把机器人任务域做成可认证的 Task ODD
持续运行与补能规模化优化中已形成排班、动态 SOC、峰平谷补能、资源排队和运力熔断闭环补能仍有人工作业与跨系统断链；机器人本体续航仅 2–4 小时高度可迁移：把电量变成生产资源约束，而非只做电池参数优化
稳定性 / 故障恢复已完成 0→1微状态、超时、重试、降级、工单、远程/现场接管和恢复条件已被运营化网络、OEM 能力和物理作业仍会阻塞；机器人跌倒恢复更难高度可迁移：状态机、资源锁、故障分级、安全港与人机接管
灵巧操作Robotaxi 未解决道路驾驶把复杂问题约束为轮式移动与标准交通交互抓握、触觉、力控、双臂协同、跌倒及技能泛化仍是机器人本体核心课题只能迁移任务降维和验收方法，不能迁移驾驶技术本身
数据与学习闭环部分解决具备车端日志、DOTA、场景回放、指标切片、版本验证和长尾挖掘范式Robotaxi 泛化仍不足；机器人数据维度更高、动作标签更贵高度可迁移：事件模型、失败样本闭环、影子验证、灰度与回滚
商业场景与 UE样板间成立Robotaxi 的服务对象、订单、收入、运力与线下成本链路明确稳定 UE、多城市/多场景 UE 打正仍在进行最高优先级迁移：先定义单任务 UE，再决定技术优先级
硬件 / BOM 成本部分解决Robotaxi 已经历传感器、计算平台、车型集成的任务定制与规模降本人形机器人执行器占 BOM 约 40%–60%，降本对象不同迁移 target-cost 与任务裁剪方法；不可直接套用零部件方案
法规、责任与社会接受路径已建立限定区域准入、测试、审计、运营责任和事故处置已有明确路径Robotaxi 仍受区域限制；人形机器人无围栏协作标准仍在起草高度可迁移：证据链、分级准入、运行域声明和安全审计

迁移顺序应从“运营闭环”开始，而不是先复制自动驾驶模型栈。P0 的判断标准是：没有它就无法证明安全、稳定完成任务或算清 UE。

这些数字证明了什么

1. Robotaxi 已能稳定把绝大多数排班资产转成实际运力。

2. 平均在线时长已接近完整工作班次，运营调度可缓冲部分硬件限制。

3. 人效远未“彻底解决”，并且高度依赖班次、场地和人工动作口径。

4. 对机器人，应优先建立相同的“计划→执行→有效产出”转化漏斗。

建议机器人一期指标树

指标域核心指标必要口径
任务交付端到端任务完成率；无人工任务完成率；单位时间合格产出按任务 ODD、机器人型号、站点、班次、版本切片
稳定性连续正常运行时长；微状态 P50/P90/P95；超时/重试/卡死率同时记录阻塞原因，不只看平均值
人工效率机器人/人；人工介入率；响应/到达/处理/关闭时长；闲置损失区分远程、现场、维护、补能和安全检查
能源效率有效作业时长占比；每任务/每小时能耗成本；补能排队损失关联任务需求、SOC、充电窗口和电价
安全安全停机率；域外拒绝正确率；人机最小距离违规；碰撞/跌倒近失按严重度建事件证据链和复盘闭环
UE单任务贡献毛利；每有效作业小时总成本；回收期；UE Gain/Loss硬件折旧、能源、场地、人工、维护、停机损失必须全量计入

边界与待确认

事实、判断与待确认的边界

已知事实：FlowUs 将机器人 P0 blocker 定义为无围栏安全和持续正常运行，并记录 Robotaxi 已完成大多数 blocker 的 0→1；昆仑看板提供了上述运营指标。

分析判断：“已解决”仅表示在限定 ODD 和运营兜底下形成闭环，不表示感知泛化、硬件可靠性或 UE 已彻底完成。

待确认：机器人首个 Task ODD、目标人效、单任务 UE、允许人工介入率、安全阈值和灰度场地均为 TBD。
