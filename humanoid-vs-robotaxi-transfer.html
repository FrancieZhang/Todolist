核心判断 Robotaxi 真正领先的不是“把所有技术难题都解决了”，而是把不完美技术约束在明确 ODD 内，并用调度、指标、人工兜底和准入证据做成可运营闭环。人形机器人最应复制的是这套 0→1 商业化系统工程。
机器人难题 Robotaxi 状态 已经做到 仍在进行 迁移判断
无围栏安全 / ODD 已完成 0→1 限定 ODD 内已有感知—规划—执行、最小风险停车、远程协助、准入与运营流程 扩 ODD 成本高；高精地图依赖与长尾泛化仍未完成 迁移方法，不迁移结论：先把机器人任务域做成可认证的 Task ODD
持续运行与补能 规模化优化中 已形成排班、动态 SOC、峰平谷补能、资源排队和运力熔断闭环 补能仍有人工作业与跨系统断链；机器人本体续航仍有限 高度可迁移：把电量变成生产资源约束，而非只做电池参数优化
稳定性 / 故障恢复 已完成 0→1 微状态、超时、重试、降级、工单、远程/现场接管和恢复条件已被运营化 网络、OEM 能力和物理作业仍会阻塞；机器人跌倒恢复更难 高度可迁移：状态机、资源锁、故障分级、安全港与人机接管
灵巧操作 Robotaxi 未解决 道路驾驶把复杂问题约束为轮式移动与标准交通交互 抓握、触觉、力控、双臂协同、跌倒及技能泛化仍是机器人本体核心课题 只能迁移任务降维和验收方法，不能迁移驾驶技术本身
数据与学习闭环 部分解决 具备车端日志、DOTA、场景回放、指标切片、版本验证和长尾挖掘范式 Robotaxi 泛化仍不足；机器人数据维度更高、动作标签更贵 高度可迁移：事件模型、失败样本闭环、影子验证、灰度与回滚
商业场景与 UE 样板间成立 Robotaxi 的服务对象、订单、收入、运力与线下成本链路明确 稳定 UE、多城市和多场景 UE 打正仍在进行 最高优先级迁移：先定义单任务 UE，再决定技术优先级
硬件 / BOM 成本 部分解决 Robotaxi 已经历传感器、计算平台、车型集成的任务定制与规模降本 人形机器人主要成本集中于执行器等不同部件，降本对象不同 迁移 target-cost 与任务裁剪方法；不可直接套用零部件方案
法规、责任与社会接受 路径已建立 限定区域准入、测试、审计、运营责任和事故处置已有明确路径 Robotaxi 仍受区域限制；人形机器人无围栏协作标准仍在完善 高度可迁移：证据链、分级准入、运行域声明和安全审计

迁移顺序应从“运营闭环”开始，而不是先复制自动驾驶模型栈。P0 的判断标准是：没有它就无法证明安全、稳定完成任务或算清 UE。

优先级 可迁移能力 机器人侧落地对象 预期价值
P0 Task ODD + 任务组合 场景、物体、动作、速度、人员距离、环境条件、失败边界 只承诺可稳定完成的任务域；域外拒绝、降级或转人工
P0 规则引擎 → 任务模块 → 微状态机 触发、前置条件、资源锁、不可跳步状态、超时、重试、完成事件 让稳定性从“模型成功率”升级为“端到端任务完成率”
P0 UE 决策引擎 机器人小时成本、替代人工时长、产出、损耗、停机、人工接管 技术路线按 UE Gain/Loss 排序，避免追求无商业价值的通用能力
P0 Fleet orchestration 机器人、工位、工具、充电位、人员、网络、时间窗、安全区 从单机 Demo 变成多机可持续生产系统
P1 异常与人机接管 可恢复、需远程、需现场、必须停机；联合计算机器人与人员 ETA 减少“人找机器人”和无效等待，沉淀异常热区
P1 补能与功耗调度 动态电量阈值、机会充电、换电、峰平谷、任务需求、排队与路程 在续航不突破时，先用调度提高有效在线率
P1 决策回放与数据闭环 输入、策略版本、资源快照、轨迹、人工动作、结果、UE 影响 定位系统性损失并为策略迭代提供可复现证据
P2 跨系统连接 ERP / WMS / MES / 门禁 / 安全系统 / 工单 / 排班接口 避免机器人形成新的运营孤岛

核心运营指标 概念与公式

排班资产运营转化率
统计期内实际进入运营且关联有效任务的去重资产数 ÷ 同期已排班且关联有效任务的去重资产数。

平均有效运营时长
统计期内各资产处于有效运营状态的时长总和 ÷ 有效运营资产日数。

人机比
日均已排班机器人数量 ÷ 日均参与对应运营工作的去重人员数量；需按班次和岗位分别计算。

有效作业时间占比
完成业务任务的有效状态时长 ÷ 可用排班窗口时长；等待、补能、故障和人工接管应单独归因。

人效需要拆分为监控、补能、清洁、维护和安全检查等工作包，不能只看一个汇总人机比。

指标体系要回答什么

1. 计划投入的机器人有多少真正转化为有效产能？

2. 有效作业、等待、补能、故障和人工处理分别消耗多少时间？

3. 哪些任务、场地、班次、机型或版本是主要损失来源？

4. 调度策略是否同时改善安全、产出、人效、能耗与 UE，而非局部优化？

指标域 核心指标与计算方式 必要口径
任务交付 端到端任务完成率＝成功完成的有效任务数 ÷ 已启动的有效任务数；无人工完成率＝未触发人工接管的成功任务数 ÷ 成功任务数 按任务 ODD、机器人型号、站点、班次、版本切片
稳定性 连续正常运行时长按相邻故障或停机事件划分区间；微状态耗时统计分位数；超时、重试、卡死率均以进入对应状态的任务数为分母 同时记录阻塞原因，不只看平均值
人工效率 人机比＝日均排班机器人 ÷ 日均去重人员；人工介入率＝触发人工动作的任务数 ÷ 已启动任务数；分别统计响应、到达、处理和关闭时长 区分远程、现场、维护、补能和安全检查
能源效率 有效作业时长占比＝有效作业时长 ÷ 可用排班窗口；单位任务能耗成本＝任务关联能耗费用 ÷ 合格任务数；补能损失按排队、路程和充电时长折算 关联任务需求、SOC、充电窗口和电价
安全 安全停机率＝安全原因停机任务数 ÷ 已启动任务数；域外拒绝正确率＝正确拒绝域外任务数 ÷ 已识别域外任务数；近失事件按严重度和暴露时长归一 建立事件证据链、审核记录和复盘闭环
UE 单任务贡献＝任务收入或等价产出价值－任务可变成本；每有效作业小时总成本＝全量运营成本 ÷ 有效作业时长；UE Gain/Loss 比较策略变更前后的收入增益与成本损失 硬件折旧、能源、场地、人工、维护、停机损失必须全量计入

边界与待确认

事实、判断与待确认的边界

已知事实：FlowUs 将机器人核心 blocker 定义为无围栏安全和持续正常运行，并记录 Robotaxi 已完成大多数 blocker 的 0→1。

分析判断：“已解决”仅表示在限定 ODD 和运营兜底下形成闭环，不表示感知泛化、硬件可靠性或 UE 已彻底完成。

待确认：机器人首个 Task ODD、目标人效、单任务 UE、允许人工介入率、安全阈值和灰度场地均为 TBD。
